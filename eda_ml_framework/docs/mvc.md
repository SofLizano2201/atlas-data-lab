# ATLAS 1.2 — MVC and extension

`app.py` composes the existing Streamlit application. The canonical package is
`src/atlas`; installing with `pip install -e .` makes it importable from Python.

## Responsibilities

| Layer | Location | Responsibility |
|---|---|---|
| Model | `models/` | Deterministic EDA, preprocessing, training, metrics, figures, comparisons and reports |
| Controller | `controllers/` | Validate requests, coordinate model calls, expose explicit capabilities |
| View | `views/` | Spanish controls, rendering and user confirmation; no scientific algorithms |
| Core | `core/` | Typed contracts, isolated session context, configuration and dependency contracts |
| Service | `services/` | Dataset activation, experiment recording and report history |
| Agent | `agents/agent.py` | Planning, specialist instructions, permitted tools, provider calls and interpretation |

Academic inheritance remains real: `ExploratoryDataAnalysis` is the parent of
`UnsupervisedLearning` and `SupervisedLearning`; `Clustering` inherits the former;
`Classification` and `Regression` inherit the latter. Initializers use `super()`.
The old Spanish class names reference these same classes through compatibility
adapters, preserving `issubclass` and inherited methods.

## Request flow

Manual: view → controller → model → result → view.
Assistant: view → AgentController → injected BaseAgent → validated capability gateway
→ existing model method → typed result → specialist interpretation → view.
Sensitive plans stop before execution and require a session-bound, expiring,
single-use confirmation. Closing assistance cancels its pending tickets.

All six agent classes are defined in one file. The five specialists override
`get_instructions`, `get_allowed_tools` and `interpret_result`; the abstract parent
owns the common `run` loop. `AgentFactory.get_agent` selects the subclass.
Controllers depend on this contract, rather than branching on concrete agents.
Provider, gateway, logger and limits can be injected. Scientific models never
import the agent layer or Streamlit.

## Reuse audit

`capability_inventory.json` records the pre-migration 104 methods (including
initializers/private entries). `capabilities_mvc.json`, generated by
`python tools/audit_capabilities.py`, lists owned public methods/properties and
the 21 gateway capabilities with input/output contracts and callable references.
These counts use different inclusion rules and should not be compared as coverage.
The inventory's test-reference flag is a discovery aid, not a coverage guarantee.

Algorithms were moved, not reimplemented in agents. Composite `profile`, outlier
diagnostics, metric-context serialization and comparison ranking were extracted
from interface/orchestration code into models. They reuse the existing calculations.
Stability guarantees, causal conclusions and automatic statistical significance
claims are not invented. Unavailable optional algorithms report their dependency.

## Extending the application

1. Implement or locate a deterministic method in the appropriate model.
2. Add an explicit controller forwarding method if needed.
3. Register a validated ToolSpec in `controllers/capabilities.py`, referencing its
   actual backend callable and documenting outputs, module and confirmation policy.
4. Permit the tool only for the appropriate specialist in `agents/agent.py`.
5. Render structured results in the shared panel; add permission and integration tests.

Do not add agent subclasses, prompts, fallback planning, or provider transports in
other modules. Do not introduce dynamic Python execution. New provider adapters
implement the existing provider contract inside the canonical agent file.

## Compatibility and limits

Root `framework`, `frontend`, `agents` and `contracts` packages only forward to the
canonical implementation. Historical Spanish output column names and problem tags
are retained for saved results and existing consumers; new configuration serialization
uses English keys. CompatibleConfiguration accepts old key lookups without duplicating
stored keys. Known live session types can be upgraded without refitting or discarding
data; this does not load arbitrary serialized models.

The UI preserves the established mockup composition. Native Streamlit controls,
local font fallbacks and responsive stacking differ from raster mockups; there is
no fake user account, search service or scheduled email delivery. Session data is
memory-only. Large-data limits remain enforced by the existing scientific layer.
